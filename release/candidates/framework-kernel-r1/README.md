# Framework kernel candidate — S1a

Base: `53e6e37724d6b387dc113ffcba244f58e2a82301` (merged reporting corrections #201–#203).
Implementation is isolated from open UX PRs #204/#205. No hosted access, SQL, migration, Edge Function, production import, publication or API spend.

## What is proved

The candidate owns and freezes an exact JSON source snapshot, resolves an exact family/edition/revision plus descriptor digest from an immutable in-memory registry, invokes a trusted code adapter, validates the resulting canonical report, binds company/report/version/period/framework/provenance, and executes the existing canonical rule engine. Missing facts remain missing. Findings are returned, never represented as accountant approval.

The SME compatibility adapter uses the existing `compileSavedReport` on an in-memory source bridge. Differential tests compare the new document and complete evaluation with the unchanged compiler. An independently constructed artificial statement vocabulary passes through the same pipeline; an injected equation fault is caught by the real rule engine. Both results have `publicationAuthorized: false` unconditionally. There is no option to turn it on. The synthetic adapter exists only in the test file; its canonical schema kind is IFRS solely because that schema has no synthetic enum. Its version is reserved `test-only/...`; it asserts no IFRS coverage.

A canonical validator strips unknown extensions. The candidate explicitly validates and preserves `reportingDependencies` so the compatibility wrapper does not silently discard the existing approval binding. The failing differential test exposed that hazard during implementation.

## What is not proved

This is NOT the complete S1 database/FINAL proof. No synthetic report is saved, approved or issued. No new framework is recognized by the live product. The registry does not authenticate users, determine adoption requirements, attest deployed code, or enforce transactional approval, retries or storage recovery. Those remain the existing production authorities until separately integrated and proven.

Descriptor hashes bind declared metadata and encoding. Adapter source hashes must be pinned by a reviewed build process; they do not prove which function executed. The proof wrapper has deterministic content identities but is not a persistent idempotency store. A supplied snapshot is test input, not evidence of an authorized hosted read.

## Why database generalization is a separate boundary

`boundary-inventory.json` is generated by the read-only `inventory.mjs`. It records exact source hashes and relevant lines from the composition parser, notes parser, composed-report assembler, compiler, immutable SQL and compiler builder.

Observed boundaries include SME-only payload enums, SME-specific presentation/notes semantics, SQL family CHECKs and receipt admission restricted to the SME 2015 identity. The compiler builder checks its output against a digest in the immutable `20261123100000` migration. Merely changing that compiler and regenerating the artifact is not a complete release plan; installed SQL must never be rewritten to match a new digest.

The inventory is source evidence only, not a hosted state inspection or a whole-repository recognition/measurement inventory.
